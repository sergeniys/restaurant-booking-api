# Restaurant Booking API test task

REST API для онлайн-бронирования столиков в ресторане.  
Выполнено со всеми бонусными требованиями.

---

## Стек технологий

- **Язык**: Python 3.11+ (протестировано на 3.11–3.14)
- **Фреймворк**: FastAPI
- **Схемы и валидация**: Pydantic v2
- **ORM / База данных**: SQLAlchemy 2.0 (asyncio) + SQLite (`aiosqlite`)
- **Миграции**: Alembic (async)
- **ASGI-сервер**: Uvicorn
- **Тестирование**: pytest, pytest-asyncio, httpx (`AsyncClient`)
- **Линтинг и типы**: Ruff, Mypy (`strict = true`)
- **Контейнеризация**: Docker, Docker Compose


---

## Быстрый запуск

### Вариант 1: Запуск через Docker Compose (одной командой)

```bash
docker compose up --build
```

Сервис запустится на порту `8000`. При запуске автоматически применятся миграции Alembic.  
Swagger-документация доступна по адресу: [http://localhost:8000/docs](http://localhost:8000/docs).

### Вариант 2: Локальный запуск

1. **Клонируйте репозиторий и перейдите в каталог**:
   ```bash
   git clone <repo_url>
   cd brontest
   ```

2. **Создайте и активируйте виртуальное окружение**:
   ```bash
   # Linux / macOS
   python3 -m venv .venv
   source .venv/bin/activate

   # Windows (PowerShell)
   python -m venv .venv
   .\.venv\Scripts\Activate.ps1
   ```

3. **Установите зависимости**:
   ```bash
   pip install -r requirements.txt
   ```

4. **Примените миграции Alembic**:
   ```bash
   alembic upgrade head
   ```

5. **Запустите сервер**:
   ```bash
   uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
   ```
   Либо:
   ```bash
   python main.py
   ```

API готово к приёму запросов на [http://localhost:8000](http://localhost:8000).

## API Эндпоинты

| Метод | Путь | Описание | Коды ответов |
|---|---|---|---|
| `POST` | `/bookings` | Создать бронь (валидация, проверка слота, max 10 столов) | `201`, `422`, `409` |
| `GET` | `/bookings` | Список броней с сортировкой, фильтром по дате и пагинацией (`?date=...&limit=20&offset=0`) | `200`, `422` |
| `GET` | `/bookings/{id}` | Получить бронь по ID | `200`, `404`, `422` |
| `DELETE` | `/bookings/{id}` | Отменить бронь (мягкая отмена: `status="cancelled"`, освобождает слот) | `200`, `404`, `409`, `422` |

- **Интерактивная документация Swagger UI**: `/docs`
- **Документация ReDoc**: `/redoc`

## Принятые решения и их обоснование

1. **Разделение `BookingCreate` и `BookingOut`**: Схема создания валидирует дату в будущем (до 90 дней) и время (слоты 12:00–22:00, по Москве), тогда как `BookingOut` наследуется от `BookingBase` напрямую — благодаря этому ранее созданные брони при чтении из базы никогда не падают с ошибками валидации дат.
2. Включён WAL и busy_timeout=5000, чтобы параллельные чтения и записи не приводили к database is locked
3. **Часовой пояс `Europe/Moscow`**: Валидация текущего момента и 90-дневного горизонта жестко привязана к часовому поясу Москвы через  `zoneinfo.ZoneInfo` для предотвращения ошибок при развертывании проекта на других часовых поясах.

## Реализованные бонусные баллы

1. **Async SQLAlchemy 2.0 + миграции Alembic**:
   - Использован `sqlite+aiosqlite`.
   - Настроен асинхронный Alembic (`alembic/env.py`) и создана миграция с индексами (включая составной индекс `ix_bookings_slot_status` по `(booking_date, booking_time, status)` для оптимизации проверки свободных столов).
2. **Пагинация списка броней**:
   - Параметры `limit` (от 1 до 100, по умолчанию 20) и `offset` (смещение >= 0).
   - В ответе возвращается `total` — суммарное число броней с учётом активного фильтра по дате.
3. **Защита от состояния гонки (Race Condition)**:
   - **Решение**: Реализован менеджер поэлементных блокировок `SlotLockManager` в сервисе. Блокировка берется исключительно на кортеж `(booking_date, booking_time)`. Запросы на разные слоты выполняются параллельно и независимо, а конкурентные запросы на один и тот же слот сериализуются в event loop.
   - База данных SQLite сконфигурирована в режиме `WAL` (`PRAGMA journal_mode=WAL`) с `PRAGMA busy_timeout=5000` для безопасной работы конкурентных транзакций.
   - Покрыто тестом `test_race_condition_protection`, в котором 10 параллельных запросов (`asyncio.gather`) борются за 1 оставшееся место: ровно 1 запрос завершается успехом (`201`), а остальные 9 получают `409 Slot is fully booked`.
4. **Тесты на pytest + httpx.AsyncClient**:
   - Покрыты все позитивные и негативные сценарии: граничные даты (сегодня, 90 дней, 91 день), все форматы имен и номеров телефонов, запрет прошедших слотов, отмена и повторная отмена, ограничение в 10 столов, пагинация и сортировка.
5. **Dockerfile и docker-compose**:
   - Настроен образ на базе `python:3.12-slim` с автоматическимb миграциzvb при старте контейнера.
6. **Линтер и проверка типов (Ruff, Mypy)**:
   - Конфигурация в `pyproject.toml`.
   - cтрогий режим `strict = true` в Mypy, форматирование по стандартам PEP 8 через Ruff.
